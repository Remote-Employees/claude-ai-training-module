💻 Code Editors - Your Professional Tools

Everyone at Remote Employees uses code editors - not just developers! We use THREE editors simultaneously.

🔵 Editor 1: VS Code (Visual Studio Code)

What it is: Most popular code editor in the world, made by Microsoft

Why we use it:

  • Very reliable and stable
  • Huge community - tons of tutorials online
  • Works with all our tools
  • Most team members are familiar with it

Think of it as: The reliable workhorse - like the Toyota of code editors

💜 Editor 2: Cursor

What it is: Modern editor designed specifically for AI integration

Why we use it:

  • Best AI integration of all three editors
  • Smart code completion and suggestions
  • AI understands your project context
  • Makes working with AI assistants smoother

Think of it as: The smart assistant sitting next to you

🟢 Editor 3: AntiGravity

What it is: Alternative modern code editor with different AI features

Why we use it:

  • Different AI model than Cursor
  • Good backup option
  • Some team members prefer it for certain tasks
  • More options = more flexibility

Think of it as: The alternative specialist for fresh perspectives

❓ Why THREE Editors? The AI Limits System

Each code editor connects to AI assistants (Claude, ChatGPT, Copilot). These AIs have usage limits:

  • You can only send X messages per hour to Claude
  • After that, you have to wait before using Claude again

Our solution: Switch to a different editor with a different AI!

9:00 AM - Working in VS Code with Claude
10:30 AM - Hit Claude's limit
10:31 AM - Switch to Cursor with Copilot (keep working!)
12:00 PM - Hit Copilot's limit
12:01 PM - Switch to AntiGravity with different AI (keep working!)
2:00 PM - Back to VS Code (Claude limit reset)

Result: You NEVER have to stop working! There's always an AI available to help you.

🎯 Key Bindings - Custom Shortcuts for Templates

Key bindings let you create custom shortcuts for text you type repeatedly. Press a key combo → entire template appears instantly!

💡 Real Example: Daily

Without keybinding: 5-10 minutes typing report structure manually every day

With keybinding: Press Ctrl+Shift+R → Complete daily template appears with today's date!

Monthly savings: 3.5 hours saved per month on dailys alone!

⚙️ How to Set Up Keybindings

  1. Open VS Code
  2. Press: Ctrl+Shift+P (Command Palette)
  3. Type: "Preferences: Configure User Snippets"
  4. Select: "markdown.json" (for .md files)
  5. Paste: Your keybinding code
  6. Save: Ctrl+S
  7. Use: Type "daily-report" and press Tab

📜 Prompts - Your AI Instructions

A Prompt is a document with instructions that tells Claude AI exactly what to do. Instead of explaining the same thing every time, you save the rules once and Claude always follows them!

💡 Why Use Prompts?

Without prompt: Every time you ask Claude to create a report, you explain:

  • "Include these sections..."
  • "Format it like this..."
  • "Don't forget to add..."
  • ⏰ Takes 5-10 minutes EVERY time!

With prompt: You save the instructions ONCE, then just say:

  • "Create meeting prompt using prompt"
  • ✅ Claude knows EXACTLY what to do!
  • ⏰ Takes 30 seconds!

📁 Where to Save Prompts

In VS Code / Cursor / AntiGravity:

  1. Create a file: meeting_prompt.md
  2. Save it in your Dropbox folder (accessible from all editors)
  3. When asking Claude: "Read this file and follow the instructions"
  4. Or copy-paste the prompt content directly to Claude

📋 Example: Meeting Prompt Template

This prompt tells Claude exactly how to format meeting notes in your daily file:

# MEETING_PROMPT v1.0

**Purpose:** Format meeting notes beautifully in daily file
**Author:** Remote Helpers HR
**Usage:** Copy this prompt to Claude or save as .md file

---

## YOUR ROLE

You are a Meeting Notes Formatter for Remote Helpers.
Your task: Take raw meeting transcript/notes and format them nicely in DD_daily.md file

---

## INPUT FORMAT

User will provide:
1. Meeting transcript (from Wispr Flow or other source)
2. Meeting topic/participants (if available)

---

## OUTPUT FORMAT

Format meeting notes with this structure in DD_daily.md:

### Meeting Header
```
## Meeting: [Topic/Title]
**Date:** [Date]
**Time:** [Time if available]
**Participants:** [List if available]
---
```

### Key Sections

1. **Key Points**
   - Extract main discussion points
   - Use bullet points for clarity
   - Highlight decisions made

2. **Action Items**
   - List all tasks/action items mentioned
   - Format: `- [ ] Task description (@Person if assigned)`
   - Prioritize by urgency

3. **Decisions Made**
   - List important decisions
   - Note who decided what

4. **Follow-up Required**
   - Items that need follow-up
   - Questions that arose
   - Missing information

5. **Key Quotes/Notes** (if applicable)
   - Important statements
   - Technical details
   - Numbers/metrics mentioned

---

## RULES

1. **Be concise** - Remove filler words from transcript
2. **Structure clearly** - Use headers and bullets
3. **Highlight action items** - These are most important
4. **Extract keywords** - Technical terms, project names, deadlines
5. **Time-stamp important moments** - If transcript has timestamps
6. **Clean up language** - Fix "ums", "ahs", grammatical errors

---

## EXAMPLE OUTPUT

```markdown
## Meeting: Project Status Update

**Date:** January 26, 2026
**Participants:** Manager, Team Lead, Employee
---

### Key Points

- Project deadline moved to Feb 15th
- New feature requirements added
- Budget approved for additional tools

### Action Items

- [ ] Update project timeline (@Employee)
- [ ] Research new tools for workflow (@Team Lead)
- [ ] Schedule client demo for Feb 10th (@Manager)

### Decisions Made

- Using Claude Code instead of manual scripting
- Daily standups at 10 AM starting next week
- Moving to agile sprints (2-week cycles)

### Follow-up Required

- Need final approval from client on design
- Waiting for IT to provision new server
- Clarify requirements for Module 3

### Keywords

`project timeline`, `agile sprint`, `Claude Code`, `Feb 15 deadline`, `client demo`

---
*Formatted with MEETING_PROMPT v1.0*
```

---

## TIPS

- If transcript is messy, clean it up
- Group related topics together
- Don't lose important details
- Make it scannable - use formatting
- Preserve all action items - nothing should be missed

📌 Two Ways to Create Plans with Claude

You will practice TWO different approaches for creating the same type of file (DD_plans.md):

  • Path 1 - Manual/Conversational Approach (Exercise 3): You type "create plans" and answer Claude's questions step-by-step. Good for when you want to think through tasks manually.
  • Path 2 - Path-Based/Automatic Approach (Exercise 4): You type "plan today based on yesterday" and copy/paste file path. Claude automatically finds incomplete tasks from yesterday's report. Good for quick morning planning.

Why learn both? Different situations need different approaches. Sometimes you want to talk through your tasks, sometimes you want to quickly continue yesterday's work!

Exercise 3: Create Plans WITH CLAUDE (Chat) EASY

Let Claude create your plans through conversation:

Exercise 4: Plan Today WITH CLAUDE (Path-Based) MOST IMPORTANT

Morning workflow - plan based on yesterday:

Exercise 5: Create End-of-Day Report MEDIUM

    • Find today's DD_daily.md in Explorer
    • Right-click → Copy Path
    • Paste the path to Claude
  5. Claude asks: do you have today's DD_plans.md? If yes:
    • Find today's DD_plans.md in Explorer
    • Right-click → Copy Path
    • Paste the path to Claude
  6. Answer questions: completed tasks, incomplete tasks, learnings, blockers, tomorrow's priorities
  7. Report file appears: Week_XX/DD/DD_report.md

Goal: Report is created FROM TODAY'S files (daily + plans) + your summary of what you did/didn't complete!
